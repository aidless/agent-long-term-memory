# 判断②：没有真·长期记忆 — 检索 ≠ 记忆

> **核心判断**：模型本身没有训练意义上的持久记忆，靠外部存储（RAG/向量库）补，但那是「检索」不是「记忆」。检索不到 = 记忆失效。

## 定义

- **检索（retrieval）**：从外部存储中**按查询定位**已有信息的过程。核心特征是「查询驱动」——没有查询就没有输出，且输出质量依赖检索质量。
- **记忆（memory）**：agent 在**跨会话/跨任务**中保留并自主利用经验的能力。核心特征是「自主性」——不依赖显式查询也能影响行为。
- **真·长期记忆**：模型权重本身携带的持久知识。当前 LLM 通过训练获得，但**训练后不可在线更新**——这是根本限制。

## 概念区分

| 维度 | 检索（RAG/向量库） | 记忆（agent 记忆系统） |
|---|---|---|
| 驱动方式 | 查询驱动 | 自主/被动 |
| 失效模式 | 检索不到 = 失效 | 遗忘/整合不当 = 失效 |
| 更新时机 | 显式写入 | 在线/持续 |
| 存储位置 | 外部（向量库/文档） | 外部 + 内部状态 |
| 本质 | 信息定位 | 经验沉淀 |

> 关键：RAG 解决「找得到」的问题，不解决「记得住」的问题。检索质量瓶颈（embedding 漂移、chunk 切分、相关性阈值）是检索失效的常见原因。

> **判断②的直接实证**：文献[4] 指出现有系统三大局限——扁平无结构存储丢失关系上下文、依赖昂贵 LLM 分类不实用、无验证机制静默积累矛盾——正是「检索≠记忆」的工程表现。文献[5] 打破「检索是记忆访问终点」的定式：**检索反馈驱动记忆再巩固**，是「检索≠记忆」的对立面探索。

## 缺口

1. **检索 vs 记忆的实证边界**：缺少「同样是外部存储，纯检索 vs 带遗忘/整合的记忆系统」在长程任务上的对照。文献[4] 的 MOSAIC 与文献[5] 的 REALM 提供了「记忆再巩固/冲突感知」的技术路径，但都未与纯检索做长程对照。
2. **记忆基准缺失**：业界缺少统一的「记忆是否真的帮助」基准——多数宣称是检索质量而非记忆能力。文献[3] SALM 提供理论框架但无统一基准；文献[4] 用 LoCoMo/HaluMem 但口径各异。
3. **在线更新限制**：LLM 权重不可在线更新，记忆只能靠外部——这决定了记忆架构的设计空间。文献[3] 的 SALM 认知架构正是为此设计（self-adaptive），文献[5] 的再巩固机制提供在线演化路径。

## 研究方向（第一阶段只立框架）

- **R2.1 检索/记忆实证对照**：设计「纯检索」vs「记忆系统（含遗忘/整合）」的长程任务对照。
- **R2.2 记忆基准**：明确「记忆帮助」的可操作判据，避免把检索质量当成记忆能力。
- **R2.3 记忆架构分类**：梳理分层（情景/语义/程序/工作）、遗忘策略、整合策略的设计空间。

## 关联

- 工程轨 `engineering/memory-system`：现有原型是「检索+遗忘+整合」混合，正是需要实证对照的对象。
- PAPER5：记忆架构污染是记忆系统的一个失效模式，作为 R2.3 的边界案例。

> **R2.1 已完成**（2026-11-01）：`experiments/r2_1_retrieval_vs_memory.py` 机械对照（纯检索 RAG vs 记忆系统自主整合+遗忘）验证**判断②——检索是查询驱动的，记忆系统通过关联更自主**。查询模糊（f=0.25<阈值0.3）时纯检索完全失败（0.000），记忆系统通过关联记忆仍命中（1.000，优势+1.000）。记忆系统对噪音鲁棒（遗忘管理清理噪音，各噪音水平命中率 1.000）。但查询完全模糊（f=0.000）时记忆也失效（关联度=0），记忆关联能力有边界。证据 `evidence/2026-11-01-r2_1-retrieval-vs-memory.json`。
> **R2.2 已完成**（2026-11-01）：`experiments/r2_2_memory_benchmark.py` 基准协议（判据 M = P(成功|模糊查询,记忆) - P(成功|模糊查询,纯检索)）**量化区分「记忆能力」与「检索质量」**。纯检索 M(模糊)=0.000（查询驱动，模糊查询=失效）；记忆系统 M(模糊)=1.000（自主，模糊查询也命中）。判据结论 MEMORY_SYSTEM——M>0 是真记忆，M≈0 是纯检索。协议通用，任何记忆系统可自检。证据 `evidence/2026-11-01-r2_2-memory-benchmark.json`。
